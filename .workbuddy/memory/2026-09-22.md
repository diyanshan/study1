## study1 项目接入 MySQL（Docker）+ Spring Data JPA

背景：项目原为纯 Web/Thymeleaf 骨架，无任何数据库依赖。本机原本**没有 MySQL 容器**（只有一个已退出的 mongo:8.0），Docker Desktop 守护进程也未启动。

### 改动
- 新增 `docker-compose.yml`：MySQL 8.0 容器 `study1-mysql`，映射 3306，库 `study1`，root/123456，utf8mb4，命名卷 `mysql-data`，带 healthcheck。
- `pom.xml`：新增 `spring-boot-starter-data-jpa` + `com.mysql:mysql-connector-j`（runtime，版本由 parent 4.1.1 管理）。
- `src/main/resources/application.properties`：datasource（支持 `MYSQL_URL/MYSQL_USER/MYSQL_PASSWORD` 环境变量覆盖）、HikariCP 连接池、JPA `ddl-auto=update`、`open-in-view=false`、`server.port=8080`。
- `User.java`：改为 `@Entity @Table(name="t_user")`，`Long id` 自增主键，`createTime` 用 `@PrePersist` 填充。
- `repository/UserRepository.java`：`interface` 继承 `JpaRepository<User, Long>`，加 `findByName` / `findByNameContaining`。
- `service/UserService.java`：构造器注入，提供 listAll / searchUserById / searchUserByName / searchUserByKeyword / createUser / deleteUser。
- `controller/UserController.java`：接口改为 `GET /user/list`、`GET /user/searchUser?id=`、`GET /user/search?keyword=`、`POST /user/create?name=`、`DELETE /user/{id}`。

### 验证结果
- 容器 healthy，`t_user` 由 Hibernate 自动建表成功（bigint auto_increment / varchar(64) not null / datetime(6)）。
- 应用启动连接 MySQL 8.0.46 成功，5 个接口全部返回正确数据，`select * from t_user` 确认落库。
- `./mvnw test` BUILD SUCCESS。

### 踩过的坑
- 本机 shell 环境注入了 `SERVER__PORT=0`（Relaxed binding 会覆盖 `server.port`），导致 Spring Boot 实际监听随机端口。查端口要用 `lsof -nP -iTCP -sTCP:LISTEN -a -p <pid>`。用户自己终端里跑仍是 8080。
- **不要用 `pkill -f <模糊模式>` 停进程**：曾用 `pkill -f "cp_xxx.argfile"` 误杀了用户在 VS Code 里的 8080 调试实例。正确做法是先 `lsof -nP -iTCP:8080 -sTCP:LISTEN` 拿到确切 PID，再 `kill <pid>`；如果 SIGTERM 无效就 `kill -9`。
- Tomcat 访问日志 `server.tomcat.accesslog.directory` 默认相对 Tomcat 临时基目录（`/var/folders/.../tomcat.8080.xxx/logs/`），必须写成 `${user.dir}/logs` 才会落在项目下；且按天切分，文件名是 `access.2026-09-22.log` 而非 `access.log`。
- Spring Boot 报错默认不返回异常信息，500 的 body 是空的，排查困难。加 `server.error.include-message=always` 后能在响应体里直接看到异常消息（上线前应删掉）。

## 接口演进（同日续）

- 新增按 id 查询：`GET /user/{id}`（路径参数）。注意 `/user/list`、`/user/hello` 等字面量路径优先级高于 `/{id}`，不会被抢走；`/user/abc` 因类型转换失败返回 400。
- 按用户要求，按 id 查询**改为返回数组**：`GET /user/{id}` 与 `GET /user/searchUser?id=` 都返回 `List<User>`，查到 `[{...}]`、查不到 `[]`，状态码统一 200（不再返回 404 和单对象）。
  - Repository 加 `List<User> findByIdIn(Collection<Long> ids)`（生成 `where id in (...)`）。
  - Service 的 `Optional<User> searchUserById` 被替换为 `List<User> searchUsersById(Long id)`。
- 修复 `Test2#/hello1` 的 500：`@Controller` 默认把返回字符串当视图名解析，返回纯文本必须加 `@ResponseBody`。
- 用户已自行把实体挪到 `com.stydy.study1.model.entity.User` 包，改代码时注意 import 路径。
